# Флот и капитаны

## Зачем это игроку (проверка по design-pillars)
- Делегирование с недосмотром: игрок отправляет капитана торговать и не видит, что с ним
  происходит в моменте — узнаёт по факту, это источник напряжения без микроменеджмента.
- Естественно даёт применение старым кораблям (не апгрейд-мусор, а специализация во флоте).
- Прямое продолжение существующей экономики (тот же рынок, тот же риск пиратов), а не
  отдельный жанр внутри игры.

## Минимальная версия (для первого плейтеста)

**Найм капитана** (в Tavern — уже есть заглушка в UI):
- Фиксированная цена найма, растущая экспоненциально с каждым следующим капитаном
  (например ×2.5-3), без жёсткого лимита в коде — экономика сама тормозит игрока.
- У капитана 2 характеристики на старте (не больше — минимальная версия):
  - **Торговое чутьё** — модификатор к цене покупки/продажи относительно игрока
    (например, от -10% до +10% по сравнению с тем, что получил бы игрок сам).
  - **Осторожность** — модификатор к шансу сбежать/спровоцировать встречу с пиратом
    (напрямую участвует в едином threat-model, см. 03-combat-threat-model.md).

**Назначение маршрута:**
- Игрок выбирает: корабль (из простаивающих) → капитан → порт А → порт Б → конкретный товар
  для перевозки в одну сторону (можно расширить на "любой выгодный" позже, но для минимальной
  версии — явный товар проще протестировать и понятнее игроку).
- Капитан циклически ходит А→Б→А, покупая/продавая по рыночной цене в момент прибытия
  (± модификатор чутья), пока не будет отозван или не потерян.

**Тик симуляции:**
- Раз в игровой "день" (уже есть ускоренные часы) — просчитывается: доплыл ли, что купил/
  продал, была ли встреча с угрозой (единая threat-model, см. отдельный файл).
- Результат — в лог/уведомление, использующее уже существующий toast-компонент (как для
  sea events и combat reward) — не изобретать новый UI-паттерн.

**Потеря:**
- Реальная — корабль и груз (и возможно капитан) могут быть потеряны насовсем. Никакого
  "спасательного" отката — иначе делегирование перестаёт быть риском.

## Открытые вопросы для решения перед реализацией
- Разовая цена найма или + периодическое жалование капитану (жалование сильнее давит на
  "не найми больше, чем можешь содержать" — рекомендую его, но это удорожает MVP; можно
  добавить вторым шагом после того, как база отработает).
- Что происходит с грузом/золотом капитана при возврате игрока в порт, где тот сейчас
  находится — просто ли сливается в Property, или нужен отдельный экран "флот"?
- Нужен ли отдельный UI-экран "Мой флот" (список капитанов+маршрутов+статус) сразу, или
  для MVP хватит уведомлений + списка в существующем Property-меню?

## Версия для роста (после того как MVP подтвердил, что это весело)
- Третья характеристика капитана — "манёвренность"/боевой навык, влияющая на шанс победить,
  если бегство не удалось (сейчас в MVP считаем, что бой всегда проигрышный, если побег
  не сработал — проще для первой версии, реализм можно добавить позже).
- Возможность назначить маршрут не на конкретный товар, а "любой выгодный" (капитан сам
  выбирает, что купить, по своему чутью) — для игроков, которые хотят меньше вмешиваться.
- Влияние репутации фракции конкретного порта на охотность капитана туда заходить.
- Отдельный экран "Флот" с полным обзором всех капитанов/маршрутов/статусов разом.

## Не делать даже в расширенной версии (см. design-pillars — держим фокус на торговле)
- Ручной бой за капитана (только автобой + лог).
- Персональные квесты/сюжетные линии капитанов — это отдельный жанр, не про торговлю.
